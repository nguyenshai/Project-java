\section{Task assignment}

\subsection{Task plan}
\label{subsec:task-plan}

The plan below details what each member is responsible for in Version 1. It
covers requirement analysis, interface design, database design and preparing the
submission. It is the planned assignment, not a record of finished work.

Codes \texttt{F01}, \texttt{F02}, \ldots\ identify functions; codes \texttt{T01},
\texttt{T02}, \ldots\ identify tasks. The subsystem of each function is shown in
the function lists in Section~\ref{subsubsec:client-user} and
Section~\ref{subsubsec:client-admin}, not in the code itself.
Each code stays the same when a table is renamed or reordered.

A task can relate to several functions, and a function can be checked against
several tasks. In V1 this link shows the scope of design and review; it does not
mean the function is already implemented.

A code range such as \hyperlink{F01}{F01}--\hyperlink{F12}{F12} covers every
function from F01 to F12; each end links to the matching function row.
Shared tasks about assembling and managing the work are not forced onto a
specific function.

\noindent\textbf{Acceptance rule:}
A task is recorded as done only after both members have checked it and
agreed to accept it.

The assignment can change with the actual workload once both members agree.
The results are recorded in Section~\ref{subsec:task-results} and are the basis
for each member's contribution.
