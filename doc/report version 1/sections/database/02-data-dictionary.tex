\paragraph{Data dictionary}
\mbox{}\par

The table below describes the attributes of the 16 entities in the ERD. For a
composite primary key, the attributes marked PK in the same entity form one key
together; each attribute on its own does not have to be unique. Attributes without
a question mark in the figure are expected to have a value; fields that may be
empty are noted in the key and nullability column.

The PostgreSQL script \texttt{script/create\_database.sql} implements this table.
Names become snake\_case (\texttt{ConversationMember.joinedAt} is
\texttt{conversation\_member.joined\_at}); identifiers are identity columns;
timestamps are stored as \texttt{timestamptz} and the database time zone is
\texttt{Asia/Ho\_Chi\_Minh}, so a reporting year runs from 1 January 00:00 local time
to the next 1 January. Value lists such as the account and request status are
\texttt{varchar} columns limited by \texttt{CHECK} constraints~\cite{ref:postgresql}.
Password hashes use PBKDF2 with a random salt per account~\cite{ref:rfc8018}.
\texttt{script/sample\_data.sql} loads sample data that simulates use of the system
from 1 October to 19 November 2026: 25 accounts in three activity profiles (highly
active, regular, and occasional or new), seven groups of two to six members, and at
least three cases of every feature. Every account uses the password
\texttt{chatapp123}.
